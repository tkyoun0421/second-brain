# 기억 운영 정책

## 목적

이 정책은 어떤 내용을 저장하고, 누가 확정하며, 오래되거나 잘못된 기억을 어떻게 처리할지 정의합니다.

빠진 기억보다 잘못된 기억이 더 위험하다는 원칙을 따릅니다.

## 저장 기준

기억은 다음 조건을 모두 만족할 때 저장합니다.

- 다음 작업에서 다시 사용할 가치가 있음
- 적용 범위를 설명할 수 있음
- 출처 또는 근거를 연결할 수 있음
- 상태를 `proposed`, `confirmed`, `verified` 중 하나로 판단할 수 있음
- 민감정보를 포함하지 않음

## 사용자 권한

사용자의 현재 지시는 모든 저장된 기억보다 우선합니다.

사용자는 언제든 다음을 요청할 수 있습니다.

- 기억 조회
- 제안 기억 확인 또는 거부
- 적용 범위 변경
- 기존 기억 수정
- 새로운 기억으로 교체
- 기억 삭제
- 전체 데이터 내보내기

## 확정 정책

### 사용자 발언으로 확정

다음 표현은 명시적 확정으로 취급할 수 있습니다.

```text
“A로 가자.”
“앞으로 pnpm을 사용해.”
“이 프로젝트에서는 ORM을 쓰지 마.”
“이 내용을 기억해줘.”
```

### 확정하지 않음

다음 표현은 후보 또는 질문입니다.

```text
“A는 어떨까?”
“A와 B 중 고민 중이야.”
“아마 A가 좋을 것 같아.”
```

불분명한 경우 AI는 `proposed`로 저장하거나 저장하지 않습니다.

## Memory Inbox

AI가 추출한 제안 기억은 Memory Inbox에 저장합니다.

- 기본 Context Pack에 포함하지 않음
- 사용자에게 목록으로 보여줄 수 있음
- 확인하면 `confirmed`
- 거부하면 삭제 또는 거부 상태
- 오랫동안 확인되지 않은 항목은 자동 확정하지 않음

관리 화면은 MVP에 포함하지 않고 MCP 대화로 검토합니다.

## 근거 정책

모든 활성 기억은 다음 중 하나를 근거로 가져야 합니다.

- GitHub Issue와 댓글
- 사용자의 명시적인 대화 메시지
- 테스트 또는 실행 결과
- 사용자가 승인한 문서
- 검증된 작업 실행 기록

AI의 추론만 있는 경우 `confirmed` 또는 `verified`가 될 수 없습니다.

Context Pack은 기억 내용과 함께 상태, 적용 범위와 출처 ID를 제공합니다.

## 수정과 삭제

일반적인 결정 변경은 기존 기억을 덮어쓰지 않고 `superseded` 처리합니다.

다음 데이터는 이력 보존보다 실제 삭제가 우선할 수 있습니다.

- 비밀번호와 인증정보
- API 키와 토큰
- 개인정보
- 사용자가 완전 삭제를 요청한 데이터
- 저장 권한이 없는 외부 데이터

삭제 시 원본, 스냅샷, 정제된 기억, 로그와 백업에 남아 있는 범위를 확인해야 합니다.

## 충돌 정책

- 현재 사용자 지시가 저장된 기억보다 우선
- 더 구체적인 범위가 일반적인 범위보다 우선
- 같은 범위의 충돌은 사용자 확인 필요
- 최신이라는 이유만으로 자동 승리하지 않음
- `superseded` 관계가 명확하면 신규 기억 적용
- 충돌이 중요한 작업 결과를 바꾼다면 작업 전 사용자에게 알림

## 실패 사례 정책

- 에러 메시지만 있으면 `observed`
- 원인이 추측이면 `hypothesis`
- 해결됐지만 검증하지 않았으면 `resolved`
- 테스트 또는 재현으로 확인했으면 `verified`
- 해결책이 다시 실패하면 `recurring`

스택 트레이스 전체는 원본이나 별도 로그로 저장하고, 기억에는 증상과 핵심 원인만 저장합니다.

## 민감정보 정책

다음 값은 저장 전 차단 또는 마스킹합니다.

- 일반적인 API 키 및 토큰 패턴
- `.env` 파일 내용
- 비밀번호와 접속 문자열
- 세션 쿠키
- 개인 식별정보

GitHub Actions와 MCP 서버는 최소 권한 토큰을 사용합니다. DB 관리자 키를 저장소, `AGENTS.md`, `CLAUDE.md`, Issue 또는 기억에 넣지 않습니다.

민감정보 검사는 완벽하지 않으므로 AI 지침, API 검증과 사용자 검토를 함께 사용합니다.

## 감사와 멱등성

모든 쓰기 도구 호출은 다음 정보를 기록합니다.

```text
요청 ID
도구 이름
호출한 에이전트와 세션
사용자 또는 인증 주체
입력의 민감정보 제거본
생성 또는 변경한 데이터 ID
성공 여부
호출 시각
```

재시도 때문에 같은 기억이나 실행 기록이 중복 생성되지 않도록 요청마다 멱등성 키를 사용합니다.

## 보존과 백업

- Issue 스냅샷은 실제 내용이 바뀐 경우에만 추가
- 대화 전문은 MVP에서 자동 저장하지 않음
- 큰 로그는 기억 테이블에 복제하지 않음
- 사용하지 않는 임시 원본의 보존 기간은 구현 단계에서 결정
- JSONL 및 Markdown 내보내기를 제공
- 공개 저장소에 개인 기억 백업 금지

## 기억 품질 평가

AI는 작업 종료 시 사용한 기억을 다음 중 하나로 평가할 수 있습니다.

```text
helpful
irrelevant
outdated
incorrect
conflicting
```

`incorrect` 또는 `outdated` 평가가 반복되면 자동 삭제하지 않고 사용자 검토 대상으로 보냅니다.

검색 순위는 확정 상태, 범위 일치, 검증 상태와 유용성 평가를 이용해 계산합니다.

## 자율 실행 정책과의 관계

기억은 행동 권한을 부여하지 않습니다.

“이 프로젝트는 Supabase를 사용한다”는 기술 결정일 뿐 DB 변경 권한이 아닙니다. 배포, DB 마이그레이션, 외부 메시지, 비용 발생과 삭제 권한은 별도의 자율 실행 정책에서 관리합니다.
