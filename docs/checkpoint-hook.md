# Codex 체크포인트 훅

> 현재 프로젝트에서는 일반 응답이 `Stop hook (blocked)`로 중단되지 않도록 자동 Stop 훅을
> 비활성화했습니다. 재사용 가치가 있는 결정이나 해결 경험은 에이전트가
> `brain_capture_auto_memory`를 직접 호출해 기록합니다. 아래 내용은 필요할 때 자동 훅을
> 다시 활성화하기 위한 참고 자료입니다.

`second-brain` 프로젝트는 Codex의 `Stop` 훅을 사용해 작업 종료 직전에 자동 메모리
체크포인트를 한 번 실행합니다. 훅 설정은 [`.codex/hooks.json`](../.codex/hooks.json)에,
실행 코드는 [`scripts/checkpoint-hook.ts`](../scripts/checkpoint-hook.ts)에 있습니다.

## 동작 순서

```text
작업 응답이 완료됨
  -> Stop 훅이 마지막 응답에 완료/결정/오류 해결 신호가 있는지 확인
  -> 신호가 있으면 한 번만 Codex를 재개
  -> Codex가 현재 작업을 짧게 평가
  -> 중요도 4점 이상 후보만 brain_capture_auto_memory 호출
  -> 4점 미만 또는 후보 없음: 저장 없이 최종 응답
```

두 번째 `Stop` 이벤트에는 Codex가 `stop_hook_active: true`를 전달하므로, 훅은 아무
출력도 하지 않습니다. 따라서 같은 종료 지점에서 계속 재개되는 루프가 생기지 않습니다.

## 저장 기준과 안전 장치

- 훅은 `완료`, `구현`, `해결`, `결정`, `선택`, `배포`, `검증`, `오류` 등의 작업 신호에만
  체크포인트를 요청합니다. 일반적인 인사나 짧은 질의응답에는 추가 호출이 없습니다.
- 실제 저장 여부는 훅이 아니라 기존 `brain_capture_auto_memory`의 중요도 판정이 정합니다.
  점수 4점 미만은 `discarded`이며 DB에 기록되지 않습니다.
- 자동 캡처 후보의 요약, 근거, 실패 상세는 한국어로 작성합니다. API 이름, 경로, 코드 식별자처럼
  번역하면 의미가 달라지는 기술 식별자만 원문으로 유지합니다.
- 자동 저장돼도 상태는 항상 `proposed`입니다. 사용자의 확인 또는 검증 없이 `confirmed`나
  `verified`가 되지 않습니다.
- 훅은 `last_assistant_message`만 사용합니다. 비안정 인터페이스인 대화 transcript를 읽지
  않고, `.env`, JWT, 비밀번호, 전체 대화 원문을 저장하거나 출력하지 않습니다.
- 체크포인트 재개 메시지는 민감정보·자격증명·일회성 노이즈를 저장하지 말라고 명시합니다.

## 최초 적용

1. Codex 앱을 완전히 종료한 뒤 `C:\second-brain` 프로젝트를 다시 엽니다.
2. 새 프로젝트 훅 검토 화면이 보이면 `checkpoint-hook.ts` 명령을 신뢰합니다.
   CLI에서는 `/hooks`에서 검토·신뢰할 수 있습니다.
3. 완료, 결정, 또는 오류 해결이 있는 작은 작업을 마친 뒤 Memory Inbox에 `proposed` 항목이
   생기는지 확인합니다.

프로젝트 로컬 훅이므로 `second-brain`을 신뢰한 상태에서만 작동합니다. 다른 프로젝트나
일반 대화에 적용하지 않으며, 전역 Codex 설정도 변경하지 않습니다.
